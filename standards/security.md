# 安全门禁

这是一份横切规范。涉及不可信输入、凭据、权限、外部网络、敏感数据、依赖或高风险
操作时，在架构、实现或发布门禁中加载，不单独增加开发阶段。

## 1. 触发条件

出现任一情况时必须执行本门禁：

- 接收用户输入、文件、网页、命令、URL 或模型生成内容。
- 读取、存储、传输或记录敏感数据与凭据。
- 增加账号、权限、网络监听、跨域或远程访问。
- 调用外部 API、下载依赖、访问第三方资源或执行付费操作。
- 修改认证、授权、加密、日志脱敏、沙箱和错误响应。
- 增加可能删除、覆盖、迁移或批量修改数据的操作。

## 2. 阻断标准

| ID | 阻断标准 | 必需证据 |
| --- | --- | --- |
| `SEC-01` | 资产、信任边界和攻击者可控输入已识别 | 边界与数据流 |
| `SEC-02` | 不可信输入经过适用校验、限制、编码或隔离 | 防护与负向测试 |
| `SEC-03` | 密钥和凭据只从受控配置读取，不进入源码、日志或交付物 | 扫描或检查记录 |
| `SEC-04` | 权限和网络暴露遵循最小必要，无默认公开高风险能力 | 权限与监听配置 |
| `SEC-05` | 外部调用、命令或危险操作有协议、目标、体积、超时和预算边界 | 调用约束 |
| `SEC-06` | 新增或升级依赖有来源、版本和必要安全依据 | 依赖记录 |
| `SEC-07` | 错误和信息输出不泄露密钥、内部路径、完整上游响应或敏感正文 | 错误与日志测试 |
| `SEC-08` | 数据删除、覆盖、迁移和备份有恢复或回滚条件 | 数据安全方案 |
| `SEC-09` | 高风险场景有负向测试；真实外部依赖检查获得显式授权 | 测试与授权记录 |

## 3. 判断与放行

- 相关 `SEC` 阻断项全部通过对应阶段门禁，才能放行。
- 不适用项必须说明为什么没有该风险。
- 安全高风险项不得由 Agent 自行豁免。
- 真实外部检查必须说明费用、配额、数据影响和恢复方式；普通离线测试不得隐式调用。
- 没有专门安全审查技能时，本清单和负向测试就是最低兜底，不能跳过。
