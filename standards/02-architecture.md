# 02 架构设计门禁

门禁编号：`G2`

## 1. 目标

确认架构足以支撑已批准需求、可以按明确边界实施、关键失败与风险可处理，并且
设计复杂度与项目规模相匹配。架构门禁评判的是设计完整性，不要求采用某一种固定
架构风格。

## 2. 适用范围

- 新项目、新版本或重要功能基线：执行完整 `G2`。
- 已有有效架构基线且不改变职责、契约、数据、关键流程或失败行为：快速变更复用
  `G2`，不建立新的架构文档。
- 标准开发：只评审受影响组件、接口、数据和流程的设计增量。
- 高风险变更：重开受影响架构分析，包括安全、数据一致性、失败恢复和回滚条件。
- 发现既有实现违反已批准架构时，先判断是修复既有设计还是改变设计；改变设计时
  必须重开架构门禁。

## 3. 进入条件

- 本次执行 `G2` 时，需求基线有效，或适用的 `G1` 增量已经 `PASS`。
- 已读取项目配置中的规模、运行环境、外部依赖和关键风险信息。

## 4. 输入与产物

输入：

- 已批准需求和验收清单。
- 项目约束、现有系统边界和不可变条件。
- 安全、数据、依赖或预算等专项约束。

必需产物：

- 执行完整 `G2` 时，使用
  [`templates/architecture.md`](../templates/architecture.md) 记录设计。
- 增量 `G2` 可以在已有架构产物、设计决策或变更记录中只补充受影响组件、契约、数据、
  失败与证据，不强制复制完整模板。
- 只保留受影响范围的需求追踪、关键决策、失败与风险记录。
- 已有有效架构基线时引用原产物版本，不重复复制未受影响内容。
- 默认在设计产物的“门禁结论”部分记录检查、证据和结论，不默认另建评审记录；低
  风险增量也可以把结论写入变更记录。
- 只有风险审批、审计、独立复核、证据争议、`WAIVER` 或组织流程明确要求时，才使用
  [`templates/gate-review.md`](../templates/gate-review.md)。

## 5. 阻断标准

| ID | 阻断标准 | 必需证据 |
| --- | --- | --- |
| `ARC-01` | 每条 Must 需求都有明确的组件、接口、数据或流程承接 | 需求追踪矩阵 |
| `ARC-02` | 组件职责、数据所有权和依赖方向清晰；没有职责重叠或循环依赖 | 组件表、依赖说明 |
| `ARC-03` | 公共接口或模块契约定义输入、输出、错误和兼容规则 | 契约摘要或引用 |
| `ARC-04` | 权威数据源和状态变化规则唯一；派生数据可恢复 | 数据所有权和生命周期 |
| `ARC-05` | 核心流程、部分失败、超时、重试、恢复或降级行为有定义 | 流程与失败矩阵 |
| `ARC-06` | 不可信输入、信任边界、凭据和敏感数据风险有处理方案 | 安全边界与缓解 |
| `ARC-07` | 每条关键需求都有可执行验证方式；关键流程可观测 | 测试映射、日志或指标 |
| `ARC-08` | 部署、资源、迁移、备份或回滚要求与项目规模匹配 | 运维约束说明 |
| `ARC-09` | 重大技术选择说明备选方案、取舍和未选择原因 | 决策记录 |
| `ARC-10` | 不存在未经确认、可能改变边界或验收方式的关键未决问题 | 开放问题状态 |
| `ARC-11` | 没有缺少必要性或成本说明的额外组件、依赖或抽象层 | 复杂度取舍说明 |

`ARC-04` 至 `ARC-08` 如因项目性质确实不适用，可以标记 `N/A`，但必须说明为什么
不存在该类风险。未知不能视为 `N/A`。

## 6. 必须返工的情况

出现以下任一情况时，门禁必须判定 `REWORK`：

- 存在无归属的 Must 需求。
- 组件之间依赖方向不清、存在循环依赖或关键职责重叠。
- 同一事实存在多个冲突的权威来源，且没有同步与恢复机制。
- 核心外部依赖或跨边界写入失败时行为未知。
- 高风险安全或数据完整性问题没有缓解方案。
- 验收条件无法映射到可执行验证方式。
- 重大技术选择只有结论，没有取舍依据。
- 架构依赖尚未确认的产品范围或授权条件。

## 7. 判断说明

- 小型项目可以使用单个进程或简单模块结构；简单不是缺陷，但边界必须清楚。
- 只有当规模、团队、部署或可靠性需求能够证明其成本时才引入额外服务。
- 架构图用于表达关系，不能替代职责、契约、状态和失败行为说明。
- “以后补安全”“上线后再考虑回滚”不能视为已处理。
- 设计中的观察项可以后续优化，但不能绕过任何阻断项。
- 快速变更必须能够指出现有架构边界；不能指明影响边界时升级任务模式。
- 标准开发只评审增量，不意味着可以不检查增量对既有契约和失败路径的影响。

## 8. 通过条件与放行规则

- 本次执行 `G2` 时，`ARC-01` 至 `ARC-11` 的适用项通过，或有理由充分的 `N/A`：
  `PASS`。
- 任一阻断标准失败：`REWORK`。
- 任一适用检查未执行、证据缺失，或证据未对应当前架构版本：`REWORK`。
- 需要继续采用已知设计缺口时，只能形成明确 `WAIVER`，不得把缺口写成已解决。
- 复用既有架构基线时记录 `REUSED` 和引用版本，不生成新的 `PASS`。

## 9. 设计变化与重开

以下变化会使架构门禁失效：

- 公共接口、数据所有权、状态机或关键流程变化。
- 新增外部系统、持久化边界、部署单元或高风险依赖。
- 为修复实现问题而改变模块职责或契约。

变化发生后，先更新架构产物并重新评审，再调整任务计划。
